## Evidence overlays and editing

Use a small consistent overlay: **Portaldot V3 testnet · UTC date/time · block · transaction hash**. Read the actual block and hash from the captured receipt; a dry-run estimate is labeled **simulation**. Show a clear **“120-second dispute window + keeper grace; wait shortened”** card when removing the countdown. Keep the uncut interval in the raw recording. Do not imply that the keeper refunded immediately or that native Scheduler executed the job.

For a fresh seeded camera with zero initial reserve, the script's planned arithmetic is below. These are expected values for rehearsal, not claims of completed transactions:

Show the actual successful income withdrawal and unchanged reserve, followed by the recorded rejected reserve-withdrawal attempt. Label a rejected live-chain simulation as a simulation; show a transaction hash only if a signed transaction actually ran. There is no dedicated `withdrawReserve` function: use the actual attempted call and rejection preserved by the rehearsal.
